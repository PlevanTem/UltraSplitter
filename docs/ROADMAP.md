# 产品路线与评测方案

状态：规划，尚未完成竞品实测。优先交付用户能下载使用的工具，再用固定样例推动改进。

## 1. GUI 与可下载应用

首个里程碑面向 Windows：下载、启动、拖入图片、查看主体与处理建议、批准需要的补全、导出素材，并一键打开输出目录。提供批量输入、清晰的进度与失败原因、结果预览和可取消操作。

验收：在未安装 Python/Node 的干净 Windows 环境走完首次拆图和导出。把本地确定性拆图与需要联网或模型授权的补全能力明确标识；桌面打包本身不代表附带图像模型或免费生成额度。其他操作系统在首个平台通过验收后排期。

## 2. 持续评测：只跟踪三个主指标

| 指标 | 口径 | 用户意义 |
| --- | --- | --- |
| 交付达标率 | 全部指定目标均可用，且无多余或重复主体的任务数 / 全部评测任务数。漏提、误忽略、污染、错误身份或不符合预定输出格式均不达标。 | 一次任务是否真正交齐可用素材。 |
| 完成耗时 | 从导入到可用文件导出的端到端耗时，报告成功任务的中位数；包含模型等待、必要重试与导出。失败任务保留耗时和状态，不能从达标率分母删除。 | 多久能拿到素材。 |
| 人工干预次数 | 完成一次任务需要的人主动纠错或补充指令次数；固定的导入/导出动作不计，必要的生成批准单独列出。 | 使用时需要盯多久、改多少次。 |

首批建议固定 30 个任务：UI、建筑、游戏各 10 个，覆盖规则宫格、不均匀布局、密集素材和截断。每个任务在运行前标定目标、允许忽略项、可接受的身份变化、输出要求；不得看完结果后调低成功条件。

按原像素提取、允许生成重建两个轨道分别统计；每种方式以固定配置跑三次，保留每次结果。UI/建筑是计划中的新增覆盖领域，现有示例不代表这两个领域已经通过评测。迭代调试集和冻结验收集分开保管；GUI 首次启动另做无环境依赖的验收。

## 3. 竞品对比与基线

- **均匀裁剪**：保留成本低、可复现的基础对照。
- **LibTV 宫格拆分**：优先比较规则与不规则宫格的独立子图交付。正式测试前记录产品地址、具体入口、版本或测试日期；第三方 Liblib 工作流不能代替 LibTV 产品能力。
- **Lovart Edit Elements**：比较主体分离、图层可编辑性与导出体验。官方说明支持主体、背景、文字分层及 PSD 导出；这与独立 PNG 素材交付需要分列验收。

先对共同支持的输入和同一交付目标进行横向比较，再单列各自特有能力。使用相同原图、目标说明、输出要求、重试上限；记录账号档位、模型配置和实际使用成本作为实验条件。无法测试或不支持的能力明确标注，不编造分数或领先结论。

参考：[Lovart 官方 Edit Elements 说明](https://www.lovart.ai/docs/edit-your-design/advanced-ai-editing)。LibTV 的具体入口与能力仍待实机核对。
